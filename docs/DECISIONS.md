# StarLine — Decision Record

Companion to `docs/SPECIFICATION.md`. Every entry here was explicitly decided by the owner or is a
pre-build audit resolution of an internal spec conflict. The spec remains the source of truth for
everything not listed here; entries are folded back into the spec on owner request.

## Owner decisions (2026-10-07, before M0)

1. **Licence:** MPL-2.0 (file-level copyleft; a future paid/closed edition stays possible).
2. **Repository:** private GitHub repo `daniilperkin/starline`, created and pushed when M0 is green.
3. **Sequencing:** M0 Foundation is a hard gate (report, then continue); M1→M4 follow milestone by
   milestone per §5.7.
4. **Toolchain:** install VS 2022 Build Tools (C++ workload) so the MSVC Rust toolchain and Tauri
   build work on this machine; the GNU toolchain stays a fallback for the headless storage CLI only.
5. **File scope — library files:** one `.starline` file may contain **multiple books** (`project`
   rows). This overrides the §3.3 rule "one `.starline` file = one `project` row". Exact v1.0 shape
   (book switcher, export scope per book, whether cross-book sharing is pulled forward from the
   v1.1 series plan) is pinned in the M0 report before M1 starts. M0 itself is unaffected: the
   schema already supports N `project` rows per file.

## Pre-build audit resolutions (spec conflicts/gaps)

1. **`synchronous` pragma:** §3.1 lists `NORMAL`, §5.3 wants `FULL` as default for files ≤ 200 MB.
   Implemented: `FULL` for files ≤ 200 MB, `NORMAL` above, user-toggleable in Settings → Reliability.
2. **`series` table missing:** `project.series_id` references it and the TS interface exists, but no
   `CREATE TABLE` is given. Added to migration 0001 following the §3.3 interface.
3. **Snowflake step 6 structure:** spec text says "4 sections (one per ¼ of Step 4)" while its own
   type (5-value `sourceKey` union) and validator ("fewer than 4 non-empty" = error) imply 5.
   Implemented as 5 sections, 1:1 with the five step-4 paragraphs; "four-page" is a length target.
   (Reconfirmed at M1.)
4. **`custom_field_def` uniqueness:** `UNIQUE (project_id, target, lore_kind, label)` does not
   enforce label uniqueness when `lore_kind IS NULL` (SQLite treats NULLs as distinct in UNIQUE).
   Implemented as two partial unique indexes with the same intent.
5. **Minor path drift:** export folder layout follows the normative §5.4.2 (part/chapter nesting);
   snapshot sidecar folder is `.starline-snapshots/` (§4.5.3/§5.4.1), not `.snapshots/` (§3.9).
6. **FTS coverage:** triggers per §3.10 on the five listed tables; `part`/`plotline` stay out of
   command-palette search for v1.0 (extend later if wanted).

## Owner decisions (2026-10-07, after M0)

6. **Target platform — phone app, web-first.** StarLine ships as a phone app. The TypeScript
   monorepo is retained and becomes an installable, offline-complete PWA (sqlite-wasm/OPFS).
   A native wrapper (Tauri 2 Mobile / Capacitor) can follow later without a rewrite; the Tauri
   desktop shell stays an internal test harness. This revisits the §2.2.2 "desktop-first" verdict
   and closes §A.4 question 4: the PWA *is* the phone app for v1.
7. **Visual identity — "star library".** Cosmic theme: deep-space canvas, starlight gold, nebula
   violet, the ✦ sparkle mark, a seeded starfield with constellation clusters. Tokens + contrast
   rules in `docs/DESIGN.md`; icons generated by `scripts/generate-icons.mjs`.
8. **Reference conventions — CatBookTracker (where possible).** The CatBookTracker stack itself
   (Kotlin/Compose/Nav3/Room) does not transfer to this TS codebase; a native-Kotlin rewrite was
   offered and declined in favour of the PWA route. Its *conventions* are adopted instead: a token
   layer with contrast guardrails, pure domain rules with unit tests, feature folders, a
   single-command gate, docs discipline, and the "accent is decoration, never text" rule.

## Owner decisions — deep question round (2026-10-08)

9. **Core purpose — plan AND write.** StarLine is one place from a single sentence to a finished
   draft: the Snowflake wizard to a scene-by-scene outline, then the manuscript written with
   characters/lore/notes at hand. The editor is a first-class surface, not an export target.
10. **Hard NOTs (binding): no multi-user/collaboration, no social/community features, no ads or
    analytics.** AI prose was deliberately left off this veto list — v1 still ships offline/no-AI
    per the spec; any AI feature would be a separate explicit owner decision, never a silent add.
11. **Look — "more cosmic".** Brighter nebulas, gentle motion (twinkle + slow drift), glow accents.
    Motion stays battery-aware: ~25 fps cap, pauses when the tab is hidden, honours
    `prefers-reduced-motion` (static sky).
12. **Phone delivery — sideloaded APK.** Capacitor wrap of the web build (chosen over HTTPS hosting
    for v1 personal use). The PWA stays the source of truth; the APK is a shipped artifact.
    adb-reverse against the dev server remains the fast live-reload loop during development.
13. **Sequencing — plan deeply first.** Feature build-out (characters/outliner/lore/timeline) only
    after a deep design pass; "everything, but plan deeply first".

## Owner decisions — planning round (2026-10-08, before the deep plan)

14. **UI language — English first, i18n-ready.** All v1 copy ships in English through a strings
    module (no hardcoded literals scattered in components); de/uk/ru slot in later without
    touching screens.
15. **AI — plan the seams, ship none.** v1 keeps the static bundled prompt library and a clean
    plugin point where an optional AI mode could attach later; zero AI code and zero network
    paths in v1 (any future AI feature needs its own explicit owner decision).
16. **Tempo and dogfooding — quality first, no schedule pressure.** Real-novel dogfooding begins
    once StarLine can hold a plan end-to-end; correctness and feel outrank speed. Build still
    proceeds in reviewable slices (each slice = a usable build).

## Owner decisions — M3 planning round (2026-10-09)

20. **M3 shape, settled before Slice 11.** Five answers from the owner, all binding:
    - **Native plugins:** `@capacitor/filesystem` + `@capacitor/share` are added in M3 — they are
      the only way a backup or export leaves the phone (mirror folder, save, share sheet).
    - **Mirror folder on Android:** the app-scoped **Documents** folder (zero permissions, no
      SAF plugin). This supersedes decision 17's "SAF mirror backups on Android" default; a real
      SAF tree picker can arrive later as its own decision. Web keeps the File System Access API
      where available and falls back to an export reminder.
    - **DOCX:** hand-written minimal OOXML zipped with `fflate` — the `docx` npm library would
      break the per-route 150 KiB gz budget. Both presets (Manuscript, Planning) are ours.
    - **Slice 12 stays one slice:** exporters + importers + the round-trip gate land together.
    - **Languages: English + Ukrainian.** No Russian, no German at launch. Ukrainian is the
      second language; fonts must carry Cyrillic (Ukrainian glyphs і ї є ґ) — bundled Inter
      subsets (latin + cyrillic) plus a Cyrillic-capable serif for writing mode, not a
      Latin-only family. `Intl.Segmenter("uk")`/`Intl.PluralRules("uk")` cover word counts and
      the four Ukrainian plural categories (one/few/many/other); all Intl data is browser-local,
      so the offline invariant holds.

21. **Slice 14 shape — notes incubator + attachments (2026-10-10).** Settled while building the
    last M3 slice:
    - **Notes stay in `idea_note`.** Four columns (`NOTE_STATUSES = inbox · incubating · used ·
      archived`) and six kinds (`NOTE_KINDS = idea · research · dialogue · scene_seed · question ·
      todo`) ride the table the schema already has. A note can be **promoted** into a real entity
      (`PROMOTE_TARGETS = character · scene · lore · plotline`); promotion copies the note's title
      and body into the target, links back via `promoted_to_type`/`promoted_to_id`, and is
      **undoable** — which required a new `deletePlotline` command so the plotline target has a
      real inverse like the other three.
    - **`note` joins the trash.** `TRASH_ENTITY_TYPES` gained `note` (`TRASH_TABLES.note =
      idea_note`), so the recycle bin covers it like every other entity.
    - **Attachments are content-addressed by SHA-256.** `attachment` + `attachment_blob`; the hash
      is the identity, so ingesting the same bytes twice reuses the row (dedup for free).
      `ATTACHMENT_MAX_BYTES = 20 MiB`; accepted mimes are PNG/JPEG/WebP/GIF plus PDF. Images get a
      256 px canvas thumbnail (`ATTACHMENT_THUMB_PX`), PDFs do not (no renderer ships in the
      bundle). Single-image slots are declared once: `IMAGE_SLOT_COLUMNS` = project→
      `cover_attachment_id`, character→`avatar_attachment_id`, lore→`image_attachment_id`;
      characters additionally get a gallery through `character_gallery`.
    - **Bytes never leave the device** (spec §5.2): the app writes blobs into the library file and
      reads them back; source links in notes open in the OS browser and StarLine never fetches
      them.
    - **Interchange split.** Attachment rows and bytes ride **only** the Markdown-folder zip
      (`zipOnly` tables `attachments` + `characterGallery`); the JSON document stays content-only
      and nulls the attachment FK columns (`nullColumns`) so it can never reference a row it does
      not carry. The project↔attachment FK cycle is resolved with `PRAGMA defer_foreign_keys =
      ON`; folder imports fill missing `created_at`/`updated_at` (`withTimestamps`); zip archives
      pin `mtime = ZIP_EPOCH` so exports stay byte-deterministic.
    - **Mentions reach scenes and notes** (`listMentionables`), so a note body can link a draft or
      another note.
    - **Quick capture on the phone:** the PWA manifest carries a `Quick capture` shortcut →
      `#/notes?capture=1` — the phone's answer to spec §4.4.2's global hotkey.

## Owner decisions — M4 planning round (2026-10-10)

22. **M4 shape, settled before Slice 17.** Four answers from the owner, all binding:
    - **Installers = release-signed APK.** Generate a release keystore **outside the repo**
      (`%USERPROFILE%\.starline\starline-release.keystore`; credentials in an untracked
      android `keystore.properties`), wire gradle `signingConfigs.release`, ship a signed
      release APK. The debug APK stays the QA artifact (it carries the DEV hooks the
      emulator suite drives); the release build carries none. Documented in
      `docs/ANDROID-RELEASE.md`.
    - **CI scope:** ONE workflow on every push to `main` + PRs running the full local gate
      suite — typecheck, biome, tests (native + browser), chaos, budget checks (bundle /
      no-network / contrast), web E2E (`verify-web`, `verify-pwa`). Emulator QA stays local:
      GitHub runners get no Android emulator, and a phone-path budget measured on a runner's
      software renderer would measure the runner.
    - **i18n first-run behaviour:** follow the system language (`uk*` → Ukrainian, else
      English), a Language control in Settings, the choice remembered per device
      (`starline.locale`). Launch languages stay English + Ukrainian (decision 20).
    - **a11y audit depth:** automated axe (already green) **plus** scripted manual checks —
      keyboard-only journey, focus order and visibility, target sizes ≥ 24 px,
      `prefers-reduced-motion`, 200 % zoom and text-spacing, non-text contrast — collected in
      a `docs/ACCESSIBILITY.md` WCAG 2.2 AA checklist with per-criterion evidence and an
      owner sign-off line. No screen-reader pass in this milestone.

## Owner decisions — Slice 15 (cloud backup) round (2026-10-11)

23. **Cloud backup shape, settled before S15a.** Four answers from the owner, all binding:
    - **No client-side encryption.** Snapshots upload as they are; the Drive `appDataFolder` is
      private to the account and encrypted at rest. A passphrase would add a "lost passphrase =
      unreadable backups" failure mode without changing who can read the files. Revisit only if
      the threat model changes.
    - **Scope: the APK *and* the PWA.** Both get cloud backup. The Drive layer (upload, download,
      manifest, queue) is shared; the sign-in differs — Android goes through Firebase Auth with
      the native picker (`@capacitor-firebase/authentication`), the PWA through Google Identity
      Services in the browser, which needs no Firebase at all. The Drive folder is keyed by the
      **Google account's `sub`** (present in both flows' ID tokens), so phone and browser land in
      the same backup folder.
    - **Cloud retention mirrors the local thinning** — keep-all 24 h, newest-per-day for 60 days,
      every manual snapshot — with a ~1 GB cap. No "keep everything".
    - **Build shape: a separate `STARLINE_CLOUD=1` flavor.** The default build ships no cloud code
      and makes no network requests; the signed APK and the deployed PWA are built with the flag.
      `scripts/check-no-network.mjs` becomes flavor-aware: strict for the default artifact, and
      aware of the Google endpoints for the cloud flavor. This is the wording revision decision 15
      / spec §5.2 anticipated: *the default build ships and makes no network requests; cloud
      backup is an explicitly enabled module.*

## Owner decisions — final push (2026-10-12)

24. **Finishing S15, slice 16, and the carry-overs.** Five answers, all binding:

    - **On-device sign-in test: emulator first** (the owner signs a Google account into the Play
      AVD once), phone after.
    - **CSS gzip budget raised 9 → 10 KiB**, with the note recorded in the budgets doc: slice 16
      adds real UI, and trimming the design to fit was the worse trade. It stays a gate.
    - **Structure templates: all four** (three-act, Hero's Journey, Save the Cat, story circle),
      **append-only into the unassigned pool, never replacing an existing scene list**, and always
      behind a preview the writer confirms.
    - **Carry-overs in this push: all four** — World category drag-nest, the corkboard/card view of
      the outline, multi-book UI (a second book inside one library), and timeline wide-zoom
      clustering.

25. **Slice 16 shape (owner, 2026-10-12).** Three answers, all binding:
    - **The daily card draws from the bundled prompt library, and that library is translated into
      Ukrainian** — which also fixes the prompts sheet, English-only until this slice. Translating
      the one library, rather than writing a second parallel content set for the card, keeps a
      single teaching voice and makes the en/uk parity test possible.
    - **The template picker lives in wizard step 8**, beside the existing "create scenes from

    - **A generated scene carries a title and a synopsis and stays in the unassigned pool.** Titles

26. **M5 — spec completion (owner, 2026-10-13).** The audit (`docs/SPEC-GAP-AUDIT.md`) triaged every
    spec item the code does not yet do into three tiers. Five answers, all binding:
    - **German ships as a third language, informal *du*.** Full parity with English and Ukrainian —
      UI catalogue, the nine-step prompt library and the four structure templates. This revises
      decision 20 (en + uk, no German): the owner asked for it after living with the Ukrainian

    - **A guided tour ships** — a button on the start screen and in Settings, plus a one-time
      dismissible offer card on first run. Twelve to fifteen stops covering every tab, the wizard
      and the key sheets; the spec's five coach-marks were the sketch, not the ceiling.
    - **The whole audit is in scope** (Tier 1 through 3) plus the four carry-overs — roughly 6-8

      independently with its gates green, per the standing convention.
    - **The Google console origins wait.** The signed APK signs in without them; only the deployed
      PWA cannot, and the owner chose to do it later.
    - **The accessibility sign-off stays the owner's** — the harness proves the checks, a human
      accepts them. The open items are summarised for a two-minute read.

## 29. The PWA sign-in repaired (owner + fix, 2026-10-14)

The owner added the authorized JavaScript origins (`https://daniilperkin.github.io` and
`http://localhost:5187`) on the web OAuth client, which cleared `origin_mismatch`. A
Playwright probe driving the deployed PWA end to end then found the second, real
blocker: `deploy-pages.yml` passed `STARLINE_GOOGLE_WEB_CLIENT_ID` with a stray
trailing double quote, so the deployed bundle sent `...googleusercontent.com%22` and
Google answered 401 `invalid_client` ("The OAuth client was not found"). The quote is
removed (`e24c4ae`); the redeployed PWA opens the real account chooser with the correct
client id and `origin=https://daniilperkin.github.io` accepted. The APKs were never
affected - their properties file is written locally without the quote.

## 30. The backdrop draws real northern constellations (owner, 2026-10-14)

The owner asked for the starfield to carry the real constellations of the northern sky,
with the colors untouched. The twelve iconic patterns (Ursa Major, Ursa Minor, Cassiopeia,
Orion, Cygnus, Lyra, Aquila, Taurus, Gemini, Leo, Bootes, Corona Borealis) now draw from
real J2000 star positions (orthographic projection, true shapes and proportions) and real
relative magnitudes; three to five appear per screen depending on width, joined by the
same faint violet lines the decorative clusters used. Placement is artistic - a phone
backdrop, not a sky simulator. The sky stays seeded, the reduced-motion and battery
behavior and the Settings toggle are unchanged, and no color token moved.
